━━━━━━━━━━ 一、專案方向 ━━━━━━━━━━

1. 第一個專案做英文單字卡，取代 Anki
   ｜Anki 字太小不能放大、難用；每天會用到，有動力做下去｜開發者｜10/21
2. 先做網頁版，不做純文字版
   ｜純文字版沒有使用意願；先碰過網頁，之後正式學時比較有概念｜開發者｜10/21
3. 簡化版網頁：Python ＋ Flask ＋ HTML ＋ CSS ＋ JavaScript
   ｜Flask 是投資儀表板用的技術，學了一舉兩得｜程式課 AI｜10/21
4. JavaScript 從一開始就用，但不當學習重點，之後再學扎實
   ｜避免之後再回頭改；先用樣板｜開發者｜10/22
5. 單機下載版優先；線上版、手機 App 有空再做
   ｜線上版要部署、資料庫、帳號登入，工作量大，4～5 位朋友用單機版就夠｜開發者｜10/22
6. 給所有人用，不只開發者本人
   ｜要給朋友（和朋友的朋友）用；所以規則不能綁開發者個人程度｜開發者｜10/22
7. 單字來源用大考中心第 1～6 級，不匯入英文課的 day 檔
   ｜只要匯入六次、格式統一｜開發者（英文老師 AI 建議）｜10/21


━━━━━━━━━━ 二、分工與學習方式 ━━━━━━━━━━

1. 開發者：系統分析、需求、使用者體驗；AI：軟體工程師，帶開發者寫程式
   ｜以前「開發者指揮、AI 寫」結果看不懂（投資儀表板）；現在「開發者指揮、AI 帶著寫」｜開發者｜10/22
2. Python、Flask 開發者自己打；HTML、CSS、JavaScript 用 AI 給的樣板並講解
   ｜自己打的才會懂；畫面語法用查的就好｜開發者＋程式課 AI｜10/21～10/22
3. 不用階段課表，做專案時用到什麼學什麼
   ｜回想語法很痛苦，而且學了不知道什麼時候用；做中學比較有感｜開發者｜10/21


━━━━━━━━━━ 三、架構 ━━━━━━━━━━

1. 一開始就把功能拆成不同檔案（modules/）
   ｜像變形金剛，加減功能只要改對應的檔案；每個檔案的程式也比較少｜開發者｜10/21
2. 一個檔案只管一件事；預設值也拆成 config/ 資料夾（review、allocation、display）
   ｜config.py 一個檔案管太多事，違反原則｜開發者｜10/22
3. 零件（modules/）不直接 print、input
   ｜之後改畫面（例如手機版）時，零件不用動｜程式課 AI｜10/21
4. 只有 storage.py 能直接讀寫資料檔
   ｜之後換存法（例如資料庫）只改一個檔案｜程式課 AI｜10/22
5. 六級用標籤分，所有卡存在同一個 cards.json
   ｜檢查重複只要找一個地方；用起來還是分級的｜程式課 AI｜10/21
6. 單字檔不放進 Claude 專案
   ｜程式讀的是開發者電腦裡的檔案；放專案會一直佔 AI 額度｜程式課 AI｜10/21


━━━━━━━━━━ 四、功能與規則 ━━━━━━━━━━

1. 評分 1～5 分，依分數排下次複習；第 5 分叫「直覺」
   ｜不要只有會／不會，要能評確定程度｜開發者｜10/21
2. 間隔越拉越長（倍數）、每天新卡上限、答錯重考等複習規則
   ｜依間隔重複學習的做法｜英文老師 AI 建議，開發者修正｜10/21
3. 今天答錯過的卡，過關後一律 1 天；上次分數、答錯次數、困難次數只看今天第一次
   ｜避免剛答錯的字隔太久才再考｜開發者（英文老師 AI 確認）｜10/21
4. 單字量測試：程度測驗（30／60／120 題）＋ 快速篩選，放在同一個入口
   ｜朋友不可能篩 6,000 字；測驗快但有誤差，篩選慢但具體，讓使用者選｜開發者｜10/22
5. 測驗結果用長條圖顯示各級正確率，依正確率分權重分配新卡（60～85% 是重點）
   ｜集中學「有點會又不太會」的級別最有效率；30% 以下先不出，避免太早碰難字｜開發者，程式課 AI 補完整區間表｜10/22
6. 每日新卡數固定一個數字（可設定），用權重比例分配，不用區間
   ｜權重是比例，總數永遠剛好等於設定的數字｜程式課 AI｜10/22
7. 快速篩選只選會／不會
   ｜要快；評熟悉度留給今日複習｜英文老師 AI 建議、開發者同意｜10/22
8. 已熟練用打勾 ✓，打勾後永遠不出現；想複習再到單字庫取消
   ｜熟的字不該一直佔複習時間｜開發者｜10/22
9. 統計用「熟悉」（看得懂）和「已掌握」（會拼）兩個不同的量
   ｜看得懂不代表會拼｜開發者｜10/22
10. 常錯單字獨立一頁，統計頁只顯示前 5 個
   ｜學久了常錯的字會有幾十到幾百個，放同一頁太亂｜開發者｜10/22
11. 中翻英先不做，排 v1.3；拼字 v3.0
   ｜先練看得懂；之後的版本再加｜英文老師 AI 建議現階段不做，開發者決定排進後續版本｜10/22
12. 每個畫面都有「？ 幫助」小助手，v1.0 就做
   ｜功能越來越多，使用者記不住操作；朋友用的第一版就要有｜開發者｜10/22
13. 下一個大功能優先做發音（v2.0）
   ｜英文老師 AI 建議｜10/21
14. 文件夾只看專案 docs/ 裡的文件
   ｜學習資料夾的文件不屬於這個專案｜開發者｜10/22


━━━━━━━━━━ 五、版本與發行 ━━━━━━━━━━

1. v1.0 前拆成 v0.1、v0.2、v0.3
   ｜一個版本太大（30～40 堂）；拆小比較有進度感｜開發者｜10/22
2. 時程用由下往上估：先估每個檔案，再加總成版本
   ｜功能要做很久，就拆成多個版本｜開發者｜10/22
3. v1.0 做 Windows 安裝檔，像遊戲一樣雙擊安裝；v1.1 做 Mac 版
   ｜朋友不用裝 Python；Mac 要用 GitHub Actions 的雲端 Mac 打包｜開發者｜10/22
4. 回饋用 Google 表單，首頁放按鈕
   ｜不需要帳號，朋友的朋友也能用；Line 只有認識的人能用｜開發者｜10/22
5. GitHub 專案設為公開
   ｜之後當作品集；放上去的東西都看得到，不放私人資料｜開發者｜10/21
6. 六千單字一起包進安裝檔，第一次打開時自動匯入
   ｜全空的單字庫對朋友沒意義；打開就要能開始背｜開發者｜10/25


━━━━━━━━━━ 六、文件 ━━━━━━━━━━

1. 文件一份一個用途，寫到看得懂、不會誤解為止
   ｜寫太短看不懂就失去意義｜開發者｜10/21～10/22
2. 文件在 Claude 專案和開發者電腦（docs/，同步 GitHub）各放一份
   ｜新 AI 只讀得到 Claude 專案；開發者要有自己的正本｜開發者｜10/22
3. 保留工作日誌，不只靠 GitHub 的存檔說明
   ｜一個檔案能寫得比一行存檔說明更具體｜開發者｜10/21
4. 程式學習交接說明、AI行為準則改成通用版，放在 04_專案\
   ｜所有專案共用，換專案只改一行｜開發者｜10/22
