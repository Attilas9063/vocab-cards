━━━━━━━━━━ 一、專案方向 ━━━━━━━━━━

1. 做英文單字卡，取代 Anki
   ｜Anki 字太小不能放大、難用；每天會用到，有動力做下去｜負責人｜10/21
2. 做網頁版，不做純文字版
   ｜純文字版沒有使用意願；要給朋友用，畫面要好操作｜負責人｜10/21
3. 簡化版網頁：Python ＋ Flask ＋ HTML ＋ CSS ＋ JavaScript
   ｜負責人的投資儀表板也是 Flask，兩個專案技術一致，之後維護比較容易｜工程師 AI｜10/21
4. JavaScript 從一開始就用
   ｜翻牌等互動之後一定要用，一開始就用可以避免之後回頭改｜負責人｜10/22
5. 單機下載版優先；線上版、手機 App 有空再做
   ｜線上版要部署、資料庫、帳號登入，工作量大，4～5 位朋友用單機版就夠｜負責人｜10/22
6. 給所有人用，不只負責人本人
   ｜要給朋友（和朋友的朋友）用；所以規則不能綁負責人個人程度｜負責人｜10/22
7. 單字來源用大考中心第 1～6 級，不匯入其他來源的單字檔
   ｜只要匯入六次、格式統一｜負責人（英文 AI 顧問建議）｜10/21


━━━━━━━━━━ 二、分工 ━━━━━━━━━━

1. 負責人：系統分析、需求、使用者體驗、測試、使用者回饋；
   工程師 AI：提出技術做法、寫所有程式（Python、Flask、HTML、CSS、JavaScript）、維護文件
   ｜比照實務上的分工；10/22～10/25 試過「負責人自己寫程式」，
     同時要理解專案和寫程式，負擔太重、進度很慢｜負責人｜10/25
   （取代 10/21～10/22「工程師 AI 帶著負責人寫程式」的分工）
2. 工程師一律交付完整檔案，負責人放進資料夾、測試、提交到 GitHub
   ｜AI 碰不到負責人的電腦；只給片段容易放錯位置｜負責人＋工程師 AI｜10/25
3. 現況摘要、工作日誌每次工作結束直接給完整檔案，不用先列修改的段落
   ｜只給修改的段落，看不出哪裡要動、哪裡不動｜負責人｜10/25
4. 本專案有自己的 Claude 專案、交接說明、AI行為準則，不跟其他用途混在一起
   ｜專案的文件和規則要獨立，新 AI 不會被其他內容帶偏｜負責人｜10/25


━━━━━━━━━━ 三、架構 ━━━━━━━━━━

1. 一開始就把功能拆成不同檔案（modules/）
   ｜像變形金剛，加減功能只要改對應的檔案；每個檔案的程式也比較少｜負責人｜10/21
2. 一個檔案只管一件事；預設值也拆成 config/ 資料夾（review、allocation、display）
   ｜config.py 一個檔案管太多事，違反原則｜負責人｜10/22
3. 零件（modules/）不直接 print、input
   ｜之後改畫面（例如手機版）時，零件不用動｜工程師 AI｜10/21
4. 只有 storage.py 能直接讀寫資料檔
   ｜之後換存法（例如資料庫）只改一個檔案｜工程師 AI｜10/22
5. 六級用標籤分，所有卡存在同一個 cards.json
   ｜檢查重複只要找一個地方；用起來還是分級的｜工程師 AI｜10/21
6. 單字檔不放進 Claude 專案
   ｜程式讀的是負責人電腦裡的檔案；放專案會一直佔 AI 額度｜工程師 AI｜10/21


━━━━━━━━━━ 四、功能與規則 ━━━━━━━━━━

1. 評分 1～5 分，依分數排下次複習；第 5 分叫「直覺」
   ｜不要只有會／不會，要能評確定程度｜負責人｜10/21
2. 間隔越拉越長（倍數）、每天新卡上限、答錯重考等複習規則
   ｜依間隔重複學習的做法｜英文 AI 顧問建議，負責人修正｜10/21
3. 今天答錯過的卡，過關後一律 1 天；上次分數、答錯次數、困難次數只看今天第一次
   ｜避免剛答錯的字隔太久才再考｜負責人（英文 AI 顧問確認）｜10/21
4. 單字量測試：程度測驗（30／60／120 題）＋ 快速篩選，放在同一個入口
   ｜朋友不可能篩 6,000 字；測驗快但有誤差，篩選慢但具體，讓使用者選｜負責人｜10/22
5. 測驗結果用長條圖顯示各級正確率，依正確率分權重分配新卡（60～85% 是重點）
   ｜集中學「有點會又不太會」的級別最有效率；30% 以下先不出，避免太早碰難字｜負責人，工程師 AI 補完整區間表｜10/22
6. 每日新卡數固定一個數字（可設定），用權重比例分配，不用區間
   ｜權重是比例，總數永遠剛好等於設定的數字｜工程師 AI｜10/22
7. 快速篩選只選會／不會
   ｜要快；評熟悉度留給今日複習｜英文 AI 顧問建議、負責人同意｜10/22
8. 已熟練用打勾 ✓，打勾後永遠不出現；想複習再到單字庫取消
   ｜熟的字不該一直佔複習時間｜負責人｜10/22
9. 統計用「熟悉」（看得懂）和「已掌握」（會拼）兩個不同的量
   ｜看得懂不代表會拼｜負責人｜10/22
10. 常錯單字獨立一頁，統計頁只顯示前 5 個
   ｜學久了常錯的字會有幾十到幾百個，放同一頁太亂｜負責人｜10/22
11. 中翻英先不做，排 v1.3；拼字 v3.0
   ｜先練看得懂；之後的版本再加｜英文 AI 顧問建議現階段不做，負責人決定排進後續版本｜10/22
12. 每個畫面都有「？ 幫助」小助手，v1.0 就做
   ｜功能越來越多，使用者記不住操作；朋友用的第一版就要有｜負責人｜10/22
13. 下一個大功能優先做發音（v2.0）
   ｜英文 AI 顧問建議｜10/21
14. 文件夾只看專案 docs/ 裡的文件
   ｜其他資料夾的文件不屬於這個專案｜負責人｜10/22


━━━━━━━━━━ 五、版本與發行 ━━━━━━━━━━

1. v1.0 前拆成 v0.1、v0.2、v0.3
   ｜一個版本太大；拆小比較有進度感｜負責人｜10/22
2. 時程用由下往上估：先估每個檔案，再加總成版本
   ｜功能要做很久，就拆成多個版本｜負責人｜10/22
3. v1.0 做 Windows 安裝檔，像遊戲一樣雙擊安裝；v1.1 做 Mac 版
   ｜朋友不用裝 Python；Mac 要用 GitHub Actions 的雲端 Mac 打包｜負責人｜10/22
4. 回饋用 Google 表單，首頁放按鈕
   ｜不需要帳號，朋友的朋友也能用；Line 只有認識的人能用｜負責人｜10/22
5. GitHub 專案設為公開
   ｜之後當作品集；放上去的東西都看得到，不放私人資料｜負責人｜10/21
6. 六千單字一起包進安裝檔，第一次打開時自動匯入
   ｜全空的單字庫對朋友沒意義；打開就要能開始背｜負責人｜10/25


━━━━━━━━━━ 六、文件 ━━━━━━━━━━

1. 文件一份一個用途，寫到看得懂、不會誤解為止
   ｜寫太短看不懂就失去意義｜負責人｜10/21～10/22
2. 文件在 Claude 專案和負責人電腦（vocab-cards 資料夾，同步 GitHub）各放一份
   ｜新 AI 只讀得到 Claude 專案；負責人要有自己的正本｜負責人｜10/22
3. 保留工作日誌，不只靠 GitHub 的存檔說明
   ｜一個檔案能寫得比一行存檔說明更具體｜負責人｜10/21
4. 交接說明、AI行為準則分成兩份，放在專案根目錄
   ｜交接說明每次交接都要看；行為準則比較少變；功能不同就分開｜負責人｜10/25
