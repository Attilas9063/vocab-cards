━━━━━━━━━━ 一、使用的技術 ━━━━━━━━━━

- Python 3.14
- Flask：讓 Python 程式變成網頁（瀏覽器打開 localhost 使用）
- HTML：網頁上有什麼（標題、按鈕、輸入框）
- CSS：網頁長什麼樣子（字體大小、顏色、排版）
- JSON：存資料的格式，長得跟 Python 的「清單裡放表」幾乎一樣
- Python 內建工具：json（讀寫 JSON）、datetime（日期計算）、random（打亂順序）
- JavaScript：讓網頁動起來（例如翻牌不重新載入整頁）。從一開始就用，
  但跟 HTML、CSS 一樣由 AI 給樣板並解釋，不當學習重點；之後再學扎實
- 打包（v1.0）：PyInstaller（把程式和 Python 包成 .exe）＋ Inno Setup（做成安裝檔）
- 版本控管：Git ＋ GitHub（目前用 VS Code 的按鈕操作）


━━━━━━━━━━ 二、程式怎麼運作（分層）━━━━━━━━━━

　　使用者
　　　↓ 在網頁上按按鈕
畫面層　templates/（HTML）、static/（CSS、JavaScript）　你看到的網頁
　　　↓
控制層　main.py　　　　　　　　　　　　　　　收到操作 → 叫對應的零件做事 → 把結果交給畫面
　　　↓
零件層　modules/*.py　　　　　　　　　　　　 真正做事：匯入、排日期、挑卡……
　　　↓
資料　　data/cards.json、data/settings.json　 存卡片、進度、設定

【規則】（一開始就要遵守）
1. 零件（modules/）不直接 print、不直接 input。
   只負責「拿到資料 → 處理 → 交回結果」（用參數和 return）。
   跟使用者溝通的事，全部交給畫面層。
   理由：之後改畫面（例如改成手機版），零件完全不用動。
2. 只有 storage.py 可以直接讀寫 data/ 裡的檔案，其他零件要存讀都透過它。
   理由：存檔方式要改（例如換成資料庫）時，只改一個檔案。
3. 可以調整的數字（每日新卡數、天數、倍數、權重）不寫死在程式裡，一律從 config/ 裡的檔案拿：
   複習相關 → config/review.py；新卡分配、測驗題數 → config/allocation.py；畫面 → config/display.py
4. 每個檔案最上面用中文註解寫一行「這個檔案負責什麼」。


━━━━━━━━━━ 三、資料長什麼樣子 ━━━━━━━━━━

【cards.json】所有卡片，是一個「清單裡放表」：每張卡是一張表，全部放進一個清單。

[
    {
        "word": "ability",
        "back": "能力（n.）<br><br>She has the ability to lead a team.<br>她有帶領團隊的能力。",
        "level": "1",
        "due": "2026-10-25",
        "interval": 3,
        "last_score": 4,
        "wrong_count": 0,
        "hard_count": 1,
        "screened": false,
        "mastered": false
    },
    ...
]

【每個欄位】
欄位名稱　　　意思　　　　　　　　　　　　　　　　　　新卡的初始值　　加入的版本
word　　　　　英文（卡片正面）　　　　　　　　　　　　匯入時填　　　　v0.1
back　　　　　背面：中文、詞性、例句（保留 <br>）　　匯入時填　　　　v0.1
level　　　　 級別："1"～"6"，手動新增的是 "自訂"　　匯入時填　　　　v0.1
due　　　　　 下次複習日，格式 "年-月-日"　　　　　　null（新卡）　　v0.2
interval　　　目前間隔天數　　　　　　　　　　　　　　0　　　　　　　 v0.2
last_score　　上次分數（今天第一次的分數）　　　　　　null　　　　　　v0.2
wrong_count　 答錯次數（評 1、2 分，同一天最多 +1）　0　　　　　　　 v0.2
hard_count　　困難次數（今天第一次評 3 分）　　　　　0　　　　　　　 v0.2
screened　　　是否已篩選過（快速篩選或程度測驗）　　false　　　　　 v0.3
mastered　　　是否已熟練（打勾 ✓）　　　　　　　　　false　　　　　 v0.3
（v1.3 會再加：starred 星號、suspended 暫停、tags 標籤）

- 新卡：due 是 null（從來沒評過分），而且 mastered 是 false
- 今天要複習的卡：due 小於或等於今天，而且 mastered 是 false
- 欄位名稱用英文，是因為程式裡要一直打；意思以上表為準

【placement.json】程度測驗結果（v0.3）。只存最近一次。

{
    "date": "2026-11-10",
    "length": 60,
    "accuracy": {"1": 0.95, "2": 0.90, "3": 0.80, "4": 0.60, "5": 0.40, "6": 0.20}
}

- accuracy：各級正確率（0～1），用來算新卡分配的權重
- 沒有這個檔案 ＝ 沒做過程度測驗

【settings.json】使用者改過的設定（v1.2 才會有）。
沒有這個檔案，或裡面沒寫的項目，就用 config/ 的預設值。


━━━━━━━━━━ 四、級別和新卡分配 ━━━━━━━━━━

- 所有卡存在同一個 cards.json，每張用 level 記住自己是第幾級（標籤的概念）。
  理由：檢查重複、存檔都只要處理一個檔案；用起來又像是分級的。
- 有 placement.json（做過程度測驗）：
  依各級正確率查權重表（config/allocation.py），按比例分配每日新卡數到各級。
  計算方式和例子見《複習規則》第八點。
- 沒有 placement.json：從第 1 級開始依序出，學完才出下一級。
- 同一級裡，照匯入時單字檔的順序（字母順序）。


━━━━━━━━━━ 五、重複判斷 ━━━━━━━━━━

- 比對英文時，先去掉前後空白、全部轉小寫再比。
  例：「Apple」「apple 」「APPLE」都算同一個字。
- 匯入單字檔、手動新增單字，共用同一套判斷。
- 重複時：匯入 → 跳過，最後告訴使用者跳過幾個；新增 → 跳通知，不加入。


━━━━━━━━━━ 六、單字檔格式（words/）━━━━━━━━━━

大考中心第 1～6 級，每級一個 .txt，每級約 1,000 字。實際內容（前幾行）：

#separator:tab
#html:true
a/an	一個、一（冠詞）（art.）<br><br>I have a dog.<br>我有一隻狗。<br><br>母音開頭的字前面用 an，例如 an apple
ability	能力（n.）<br><br>She has the ability to lead a team.<br>她有帶領團隊的能力。
able	能夠的（adj.）<br><br>I am able to swim.<br>我會游泳。<br><br>be able to ＝ 能夠（跟 can 意思接近）

讀取規則：
- # 開頭的行：說明，跳過
- 其他每一行：用 Tab（定位字元）切成兩半，左邊是英文、右邊是背面
- <br> 是換行標記：存進 cards.json 時保留，網頁顯示時就會自動換行
- 少數正面不是單一個字，例如「a/an」「he (him, his, himself)」：
  翻牌照常顯示；v2.0 做發音時再處理
- 已檢查第 1 級：1,002 行、每行都是兩半、沒有重複

級別從檔名判斷（例如「大考中心_第1級.txt」→ level "1"）。
單字檔留在學習者電腦裡，不放進 Claude 專案。

【第一次啟動自動匯入】（v1.0）
- 程式啟動時檢查 data/cards.json：
  · 沒有這個檔案（第一次打開）→ 自動匯入 words/ 裡第 1～6 級全部單字，存成 cards.json
  · 已經有這個檔案 → 直接讀，不重新匯入（才不會蓋掉複習進度）
- 打包時 words/ 要一起包進安裝檔
- 細節（例如匯入時畫面顯示「準備中」）做到 v1.0 時再訂


━━━━━━━━━━ 七、新增功能的標準流程 ━━━━━━━━━━

1. modules/ 新增或修改零件（.py）：負責處理資料
2. templates/ 新增或修改畫面（.html）
3. main.py 把網址接到零件和畫面
4. 小助手（v1.0 起）：在 helper.py 補上這個功能的操作說明
5. 測試：照《測試清單》（第一個功能做完時建立）
6. 提交（commit）並同步到 GitHub
7. 更新文件：工作日誌、現況摘要；有新檔案時更新檔案總覽；結構有變更新本文件
